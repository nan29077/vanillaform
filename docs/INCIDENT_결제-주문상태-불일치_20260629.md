## 3. 근본 원인

### 원인 A — 결제 콜백 멱등성(idempotency) 부재 (🔴 핵심)

SeedPay 결제창은 결과 콜백(`/api/payments/seedpay/result`)을 **두 번 호출**하는 경우가 있음(창 재제출/뒤로가기/PG 중복 통지 등).

1. **1차 호출**: 정상 승인 → 주문을 `PAID / COMPLETED`로 저장 ✅
2. **2차 호출**: SeedPay가 이미 사용된 인증토큰 재사용으로 보고 `resultCd=9999`(비정상 접근) 반환
3. 기존 코드는 `resultCd !== "0000"`이면 **주문의 현재 상태를 보지 않고 무조건** `markOrderFailed()` 실행
4. → **이미 결제완료된 주문을 `CANCELLED / FAILED`로 덮어씀** ❌

즉 "이미 결제완료된 주문은 건드리지 않는다"는 방어 로직이 없던 것이 직접 원인.

### 원인 B — PG 직접취소 시 DB 미동기화 (🟡)

SeedPay 관리자 화면에서 직접 전취소하면 서비스 `/cancel` API를 거치지 않아 DB가 갱신되지 않음. (B17YT1)

### 원인 C — 이탈 주문이 목록에 노출 (🟢)

미결제 이탈 주문은 `CANCELLED`로 전환되는데, 기존 "이탈 자동정리"는 `PENDING`만 삭제 대상으로 봄. 주문 목록 필터도 `PENDING`만 제외 → 이탈 `CANCELLED`가 그대로 "취소됨"으로 노출되어 혼란 유발.
