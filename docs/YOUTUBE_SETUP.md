# YouTube 연동 — 설정 및 남은 작업

셀러 라이브 커머스의 YouTube 연동(채널 연결·라이브 감지·채팅 전달/봇)에 필요한
Google Cloud 설정과 앞으로 해야 할 작업을 정리한 문서.

- Google Cloud 프로젝트 번호: `842904850253`
- OAuth 클라이언트: `842904850253-4r0egq7....apps.googleusercontent.com`
- 리디렉션 URI: `http://localhost:3026/api/auth/youtube/callback`
- 요청 스코프: `https://www.googleapis.com/auth/youtube.force-ssl` (민감한 범위)

---

## 1. YouTube Data API v3 사용 설정 — 최우선 ⛔ 미완료

이게 꺼져 있으면 **연결에 성공해도 기능이 전혀 동작하지 않는다.**
채널 정보 조회, 라이브 방송 자동 감지, 채팅 전송이 전부 `403 accessNotConfigured` 로 실패한다.

### 하는 법

1. 아래 링크 접속 (프로젝트가 이미 지정돼 있음)
   ```
   https://console.developers.google.com/apis/api/youtube.googleapis.com/overview?project=842904850253
   ```
2. **사용 설정(Enable)** 클릭
3. 2~5분 대기 (Google 시스템 전파 시간)

### 확인 방법

셀러 계정으로 `/seller/live` → 유튜브 연결을 **다시 한 번** 실행한다.
채널명이 화면에 표시되면 성공.

> ⚠️ 이미 연결한 셀러(하늘 Pick)는 API가 꺼진 상태에서 연결해 채널명·채널ID가 `null` 로
> 남아 있다. `status` API 는 DB 값을 읽기만 하므로 자동으로 채워지지 않는다. **재연결 필요.**

## 2. OAuth 동의 화면 — 프로덕션 게시 + 앱 인증 ⛔ 미완료

현재 게시 상태가 **테스트(Testing)** 라서, 등록된 테스트 사용자 외에는
`403 access_denied — Google 인증 절차를 완료하지 않았습니다` 가 뜬다.

### 2-1. 당장 쓰려면 — 테스트 사용자 추가 (임시)

```
Google Cloud Console → 프로젝트 842904850253
→ API 및 서비스 → OAuth 동의 화면 → 대상(Audience)
→ 테스트 사용자 → 사용자 추가
```

연결할 셀러의 Google 계정 이메일을 추가하면 즉시 사용 가능.

**단, 운영에는 부적합하다:**

| 제약 | 내용 |
|---|---|
| 인원 | 테스트 사용자 최대 100명 |
| 토큰 만료 | **refresh token 이 7일 후 만료** |

7일 만료가 특히 문제다. 만료되면 `refreshYoutubeToken()` 이 실패하고
채팅봇이 **아무 안내 없이** 멈춘다. 셀러가 매주 재연결해야 한다.

### 2-2. 근본 해결 — 프로덕션 게시 + 인증 신청

같은 화면에서 **프로덕션으로 게시**. `youtube.force-ssl` 은 Google 이 **민감한 범위**로
분류하므로 인증(verification) 검토를 받아야 제한 없이 쓸 수 있다.

#### 준비물 체크리스트

- [x] 홈페이지 URL — `http://localhost:3026`
- [x] 개인정보처리방침 URL — `http://localhost:3026/support/privacy`
- [ ] **도메인 소유권 확인** — Google Search Console 에 `vanillaform.co.kr` 등록
      (Console 의 확인된 도메인과 OAuth 동의 화면의 승인된 도메인이 일치해야 함)
- [ ] **앱 시연 영상** — YouTube 에 업로드(비공개 아님, 미등록 가능)
      - 담아야 할 내용: 로그인 → 셀러 대시보드 → 유튜브 연결 버튼 → **Google 동의 화면
        (요청 스코프가 화면에 보이게)** → 연결 완료 → 실제로 라이브 채팅에 메시지가
        전송되는 장면
      - 스코프가 왜 필요한지 동작으로 보여주는 게 핵심. 동의 화면을 건너뛰면 반려된다.
- [ ] **범위 사용 사유 작성** — 예시:
      > 셀러(인플루언서)가 자신의 YouTube 라이브 방송을 바닐라폼 라이브 커머스 페이지와
      > 연동합니다. `youtube.force-ssl` 은 (1) 셀러 본인의 진행 중 방송을 자동 감지하고
      > (`liveBroadcasts.list`), (2) 사이트 채팅에 올라온 구매자 문의를 셀러의 YouTube
      > 라이브 채팅으로 전달하기 위해(`liveChatMessages.insert`) 필요합니다.
      > 셀러 본인이 명시적으로 연결을 승인한 자신의 채널에만 접근합니다.
- [ ] 브랜드 정보(앱 이름·로고·지원 이메일) 최종 확인

#### 진행 시 참고

- 검토 기간은 보통 며칠~몇 주. 추가 자료 요청이 오면 회신해야 진행된다.
- 검토 중에도 프로덕션 게시 상태면 "확인되지 않은 앱" 경고 화면을 거쳐 사용은 가능하지만
  누적 사용자 수에 제한이 걸린다.
- 민감한 범위라 보안 평가(security assessment)까지는 요구되지 않는다.
  (그건 Gmail/Drive 같은 제한된 범위 대상)

## 3. 채팅 발신 명의를 "바닐라폼" 로 — 📋 계획 단계

### 현재 상태 (2026-07-29 배포)

YouTube Data API 는 **OAuth 인증 계정 명의로만** 게시된다. 표시 이름·아바타를 지정하는
파라미터가 없다(Slack/Discord 의 webhook username override 같은 개념 없음).
따라서 지금은 셀러 채널이 직접 친 것처럼 보인다.

우선 본문 프리픽스로 발신 주체를 구분하도록 조치했다.

```
[바닐라폼] 윤세일: ㅎㅇ          ← 사이트 채팅 전달
[바닐라폼] 지금 구매하면 10% 할인!  ← 챗봇 메시지
```

### 근본 해결 — 전용 봇 계정 분리

"바닐라폼" 이름의 **별도 Google 계정 + YouTube 채널**을 만들어 그 계정으로 OAuth 연결하고,
**전송만** 봇 토큰으로 하면 채팅에 바닐라폼 이름·프로필로 표시된다.

토큰 역할 분리:

| 용도 | 토큰 | 이유 |
|---|---|---|
| 방송 자동 감지 (`liveBroadcasts.list mine=true`) | 셀러 토큰 (현행 유지) | 본인 방송은 본인 계정만 조회 가능 |
| liveChatId 조회 (`videos.list`) | 봇 토큰 가능 | 공개 영상 정보 |
| 메시지 전송 (`liveChat/messages`) | **봇 토큰** | 이게 표시 명의를 결정 |

#### 선행 작업 (사람이 해야 함)

- [ ] 바닐라폼 명의 Google 계정 생성
- [ ] 해당 계정에 **YouTube 채널 생성** (계정만으로는 채팅 불가)
- [ ] 프로필 이미지·채널명을 바닐라폼 브랜드로 설정
- [ ] 계정에 어느 정도 활동 이력 쌓기 (신규 계정은 스팸 필터에 숨겨질 수 있음)

#### 코드 작업

- [ ] 스키마: 봇 계정 토큰 저장소 (`SystemConfig` 확장 또는 신규 모델)
      — 알리고 발신계정처럼 관리자 통합 관리
- [ ] 관리자 화면에 봇 계정 연결/해제 UI
- [ ] `youtubeChatForward.ts` / `chatbot/route.ts` 전송을 봇 토큰으로 전환
- [ ] **`youtube-sync/route.ts` 에코 필터를 봇 채널ID 기준으로 변경** ← 빼먹으면
      전달 메시지가 사이트 채팅에 중복 표시된다
- [ ] 프리픽스 정리 — 발신자명이 이미 바닐라폼이므로 `[바닐라폼]` 를 떼고
      `윤세일: ㅎㅇ` 형태로 단순화 가능 (에코 필터도 함께 수정)

#### 운영 주의사항

- 각 셀러가 자기 채널에서 바닐라폼 계정을 **모더레이터로 지정**해두면 스팸 필터·차단 위험이 준다
- 스트리머가 봇 계정을 차단/타임아웃할 수 있다
- 봇 계정 1개를 전 셀러가 공유하므로 동시 방송이 많아지면 계정 단위 채팅 속도 제한에 걸릴 수 있다
  (현재 라이브당 10회/분 제한 — `youtubeChatForward.ts`)
- API 쿼터는 지금과 동일하게 프로젝트 단위

## 4. 토큰 만료 시 셀러 안내 — 📋 미착수

`refreshYoutubeToken()` 은 갱신 실패 시 `null` 만 반환하고 끝난다(`lib/youtubeOAuth.ts`).
테스트 모드의 7일 만료, 셀러의 권한 회수, 계정 비밀번호 변경 등으로 토큰이 죽어도
**셀러 화면에 아무 안내가 뜨지 않아** 채팅봇이 왜 멈췄는지 알 수 없다.

- [ ] 갱신 실패 시 DB 토큰 정리 + "유튜브 재연결 필요" 상태 노출
